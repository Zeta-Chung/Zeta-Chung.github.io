2-1.程序编码和数据格式

第20篇 发表于 2026-11-11 更新于 2026-11-12

CSAPP第三章学习笔记，内容包括机器代码的特征和生成、架构中的数据格式，笔记涉及的架构均为x86-64。

机器级代码

是什么

  1. 所处抽象层次:直接涉及机器指令、寄存器和内存地址

  2. 包括汇编指令和机器码

机器级代码不等于机器码

机器级编程的两种重要抽象

指令集架构(ISA)

  1. 是什么: 软件和硬件的接口，规定软件操作对应的硬件行为。

  2. 做什么: 定义机器级程序的格式和行为，包括处理器状态，指令的格式和每条指令对状态的影响

  3. 为什么需要: 实现软硬件的分离处理，让软件开发者不必纠结于CPU的内部结构

虚拟内存

参见虚拟内存

机器级代码中可见的处理器状态

  1. 程序计数器(PC): 存储将要执行的下一条指令在在内存中的位置, 在x86-64中用%rip表示

  2. 整数寄存器文件: 包含16个寄存器的名称，分别存储64位的值, 用于不同的功能。

  3. 条件码寄存器:保存最近执行的算数或逻辑指令的状态信息，用于实现控制数据流的条件变化(比如if和while)

  4. 向量寄存器: 存放一个或多个整数或浮点数值

机器级代码的生成

编译工具:gcc

目前需要使用的命令:

  • gcc -Og -o p file.c
  • gcc -Og -S file.c
  • gcc -Og -c file.c

参数解释:

  1. -Og: 告诉编译器使用会生成符合原始C代码整体结构的机器代码的优化等级。

理解:编译时做一些优化, 同时尽量让生成的代码便于与原始C代码对应, 方便阅读和调试, 因此作为学习工具。如果用较高级别的优化，例如参数-O1或 -O2，程序优化效率更高，但产生的代码结构会发生很大改变。

  1. -o p: 把最终产生的可执行文件命名为p

  2. -S: 编译程序，产生汇编代码

  3. -c: 编译并汇编代码，产生目标文件.o(未产生可执行文件)

反汇编

基本信息

  1. 是什么:根据机器码产生可读的汇编代码的格式

  2. 为什么需要:查看机器码的实际内容

  3. 实际操作:objdump -d file.o，反汇编并在命令行汇总打印

注意事项

  1. x86-64的指令长度1-15字节，具体长度由指令及其操作数的编码方式决定。

  2. 设置指令格式的方式:从某个给定位置开始，可以将字节唯一解码成机器指令。

  3. 反汇编器基于机器代码文件中的字节序列确定汇编代码，没有访问程序的源代码或汇编代码。

  4. 反汇编器生成的汇编代码和GCC生成的汇编代码由于命名规则差异，会有细微差别，但功能相同。

结合C和汇编代码

  1. 为什么需要: C程序不能访问一些机器特性，使用汇编能够简化流程

  2. 两种方法

    1. 编写完整函数，放进独立汇编文件，让汇编器和链接器完成合并

    2. 使用gcc的内联汇编特性，用asm伪指令使C程序中直接包含汇编代码(更常用)
